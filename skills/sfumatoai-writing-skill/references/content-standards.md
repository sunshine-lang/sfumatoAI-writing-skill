# 内容标准

## 目录

1. 受众与目标
2. 选题判断
3. 研究与证据
4. 概念表达
5. 脚本结构
6. 标题与正文

## 1. 受众与目标

面向对 AI 感兴趣、缺少技术背景的小白。让读者看完后能回答一个明确问题，而不是只记住一组名词。

把“故事性、简洁、准确”同时作为目标：

- 用场景降低理解门槛；
- 用定义完成准确收口；
- 用边界避免夸大；
- 用一条主线控制信息密度。

## 2. 选题判断

不要盲目吞读素材。先寻找最值得发布的一条知识增量，并按以下维度评分：

| 维度 | 判断问题 |
|---|---|
| 受众价值 | AI 小白为什么现在需要知道？ |
| 单一主张 | 能否用一句话说清本组只讲什么？ |
| 视觉叙事 | 能否转化成动作、变化、对比或因果？ |
| 证据质量 | 是否能找到两份以上可靠来源？ |
| 误解价值 | 是否能纠正常见但重要的误解？ |
| 范围控制 | 4–7 张能否讲清，不需要堆满术语？ |

若素材包含多个强方向，给出“推荐 + 两个备选”，不要让用户从零选题。

## 3. 研究与证据

任何技术选题方案都必须先完成初步检索。先验证概念范围、核心机制和主要误解，再决定哪条主线值得发布；不要先凭印象提出选题，再把搜索当成确认后的步骤。

### 来源优先级

1. 官方技术文档、标准、原始论文、产品原始说明；
2. 可靠机构的解释或研究；
3. 高质量二手文章；
4. 社交媒体截图和营销文案，只作为待核验线索。

关键定义至少交叉验证两份来源。来源之间有口径差异时，说明本文采用的操作性定义和适用范围。

### 必须追问的歧义

- 同一缩写对应多个概念；
- 产品名与通用技术名混用；
- 用户想讲行业概念还是某个具体产品；
- 不同时间版本会改变结论；
- 不同目标受众会改变解释深度。

### 禁止直接采用的表达

- “终极形态”“完全取代”“保证成功”；
- “只给目标就能完成一切”；
- “会思考”“有意识”而没有准确解释；
- 把常见增强项写成所有系统的必备项；
- 把已接入的工具能力写成无限现实权限。

## 4. 概念表达

使用三层表达：

1. **故事句：**读者熟悉的任务或冲突；
2. **机制句：**系统实际做了什么；
3. **边界句：**什么条件下不成立、会失败或应交给人。

比喻出现后，必须补一条非拟人化的准确表述。不要用组件堆砌代替机制解释。

## 5. 脚本结构

- 每页只承担一个主要认知任务。
- 顶部文字提出本页判断，底部文字完成解释或边界。
- 中部画面展示动作、对象关系或状态变化。
- 真实说话动作可以使用气泡；旁白不要放进气泡。
- 结尾不能只喊口号，应给出可复述定义、适用条件或风险。

推荐逐页字段：

```markdown
### 第 N 张：页面角色
- 页面任务：
- 顶部文字：
- 底部文字：
- 画面动作：
- 事实边界：
```

## 6. 标题与正文

### 标题

- 提供 1 个推荐、2 个备选；
- 推荐标题优先对应封面问题；
- 避免“震惊”“封神”“终极”等无法证明的强词；
- 不用术语堆砌制造专业感。

### 正文

- 不超过 200 个字符，不计换行；
- 开头承接封面或故事场景；
- 中段说明核心认知增量；
- 结尾补充能力边界或使用提醒；
- 不逐页复述图片，不塞入长来源列表。
