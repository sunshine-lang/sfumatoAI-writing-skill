# 交付与验收规范

## 目录

1. 审批关卡
2. 文件结构
3. 交付清单
4. 自动检查
5. 人工检查

## 1. 审批关卡

按顺序获得确认：

1. 选题与概念范围；
2. 页数与逐页脚本；
3. 视觉风格或 A/B 校准图；
4. 整组成图；
5. 正文与话题；
6. 安装、发布或开源等外部动作。

用户可以一次性明确授权多个后续关卡；否则不要把沉默视为确认。

## 2. 文件结构

```text
topic/
├── research.md
├── script.md
├── delivery.md
├── manifest.json
├── raw/
├── text/
├── final/
└── revisions/
```

只把当前采用版本放入 `final/`。把未采用候选留在 `revisions/` 并标明状态。

## 3. 交付清单

- 1 个推荐标题；
- 2 个备选标题；
- 200 字以内正文；
- 与内容匹配的话题组合；用户要求流量分析时，附检索日期、样本范围和 A/B 替换项；
- 至少 4 张严格 3:4 图片，第一张为封面；
- 逐页脚本；
- 研究底稿与直接来源链接；
- 图像生成提示词或可复现规格；
- 自动与人工质检结果；
- 已知限制和未采用版本说明。

使用 [delivery-manifest.template.json](../assets/delivery-manifest.template.json) 创建主题交付清单。

## 4. 自动检查

运行：

```bash
python3 scripts/validate_delivery.py /absolute/path/to/manifest.json
```

脚本检查：

- 推荐标题非空；
- 恰好两个备选标题且不重复；
- 正文不超过 200 个字符（不计换行）；
- 正文内没有大小写变体或完全相同的重复话题；
- 至少 4 张图片；
- 第一张且仅第一张标记为封面；
- PNG/JPEG 图片存在并严格满足 3:4；
- 至少两条带 HTTP(S) 链接的来源。

自动检查不能验证事实是否正确、画面是否美观、伪文字是否存在或人物是否符合用户偏好。

## 5. 人工检查

### 内容

- 核心结论是否与来源相符；
- 比喻后是否有准确收口；
- 是否出现保证成功、无限权限或过度拟人；
- 正文是否与图片互补而非复述；
- Emoji 是否承担导航作用且没有装饰性堆叠；
- 话题是否与标题、正文和图片一致；
- 流量建议是否标明平台采样日期、范围和相关性边界。

### 视觉

- 封面缩略图是否可读；
- 文字层级是否明确；
- 内页文字位置是否合规；
- 颜色、线条、纸张肌理和人物识别是否一致；
- 是否出现角标、文字底板、伪文字、水印、额外人物或无关 UI。

### 技术

- 图片顺序、数量和命名是否正确；
- 所有最终文件是否能打开；
- 原版和返修版是否没有被误覆盖；
- 本地路径是否可点击或可复制；
- 对外发布前是否获得明确授权。
