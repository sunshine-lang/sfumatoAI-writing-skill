# 已审核案例：Agent 与聊天 AI 的差别

## 输入与选题判断

用户提供人物参考图、两张资料截图，以及 Google Cloud 和 Anthropic 的 Agent 文章。截图包含“AI 终极形态”“只给目标”“自动纠错直到完成”等夸张说法。

最终没有照抄“什么是 Agent”，而是选择小白更容易产生认知增量的问题：

> Agent 到底比聊天 AI 多做了什么？

内容范围限定为由大语言模型驱动的 Agent。

## 研究结论

使用 Google Cloud、Anthropic、OpenAI、ReAct 和 Reflexion 等一手资料核验后，采用以下核心表述：

> Agent 是在目标和边界内，调用工具、根据反馈继续行动的 AI 系统。

保留以下边界：

- 工具必须事先接入并授权；
- Agent 可以根据反馈调整，但不保证成功；
- 长期记忆、RAG、显式规划、自我反思和多 Agent 不是所有 Agent 的统一必备项；
- 付款等高风险操作应由人确认。

## 六页故事线

1. 封面：`Agent / 到底多做了什么？`
2. 一句话安排旅行，背后包含天气、车次、酒店和行程等任务。
3. 没有执行工具的聊天 AI 给出攻略，但实际操作仍由用户完成。
4. Agent 从已授权工具中选择一项，获取信息或执行操作。
5. 结果变化后，Agent 调整下一步，继续、停止或向人求助。
6. 用准确概念收口，并强调失败风险与人工确认。

让 AI 帮你安排旅行，它是只写一份攻略，还是会继续查车次、比酒店、根据结果调整下一步？

这组图从一个旅行场景出发，讲清没有执行工具的聊天 AI 和 Agent 到底差在哪。

Agent 不是“更像人”，而是在目标、权限和规则内调用工具、推进任务。但它也会犯错：没接入的工具用不了，付款等高风险操作仍应由人确认。

- 采用 A+：长春花蓝纯色背景、复古编辑漫画、适度粗线条和较强封面对比度；
- 删除全部四角角标；
- 删除标题和说明文字底板；
- 仅在真实对白中保留气泡；
- 图像模型生成无字底图，中文后期确定性排版；
- 人物青年化返修候选经用户审查后未采用，正式组保留更亲和的原版。

## 可复用经验

1. 资料篇幅不等于选题价值。
2. 生活场景应服务机制解释，不能替代定义。
3. “同脸”不是最高优先级；人物识别、故事表现和用户偏好共同决定是否返修。
4. 技术概念的结尾必须保留权限、失败和人工接管边界。
